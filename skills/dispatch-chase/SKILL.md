# Chase

Verify current root ownership and a reachable Beads graph per [project state](../dispatch/references/project-state.md) before any write or worker action. A non-owner may inspect only; takeover must be explicit.

Read the [Dispatch role](../dispatch/SKILL.md), [worker contract](../dispatch/references/cooper-workers.md), and **Track** in [work items](../dispatch/references/work-items.md). A scheduled run is merely a trigger to this same procedure, not a broader authorization.

1. Load this thread's root and verified ownership, its descendants (`bd list --all --include-gates --limit 0 --json`), open decisions, worker destinations from `t3.*` metadata, and pending gates. Finish any launch or update in hand before processing newly arrived completion hints.
2. Follow [freshness reconciliation](../dispatch/references/board-page.md#reconcile-before-presenting): snapshot every known owner's exact live runtime, latest/active run, pending input and new activity and comments since `t3.cursor`. Run `bd gate check`. A past final report cannot establish current completion; resumed execution goes back to Now. Record per-worker verification timestamps and distinguish active local owners from cards and external coordination. Read reports and pending questions through T3, plus current PR head, CI, and reviews. Follow pages/truncated messages. A worker-local report path cannot substitute for its T3 reply. Do not scan unrelated threads or wake a worker to ask for status.
3. Drain reports in a batch through [Report](../dispatch/playbooks/report.md), with queue refill deferred until this pass finishes. Record each report on its issue, advance its cursor, and preserve any unresolved human gate. New arrivals wait for the next pass. Repeated hints are harmless.
4. Chase concrete problems inside the approved job: send the active Cooper a specific failing check or review finding to address. Preserve its design and forbidden actions. Reuse the worker for that job; separate scopes and settled workers get new briefs. An interrupted or idle run without a report is not automatically dead. Read the latest run and pending input before deciding whether to continue, report access failure, or propose replacement.
5. Keep `human` merge-ready PRs owned and visible until Dan's merge decision. After Dan approves one, record the decision and send its worker the merge follow-up. A new head SHA invalidates the old verification claim. Obtain fresh verification through Cooper. Dispatch never fixes code, and merges only under the [merge policy](../dispatch/references/cooper-workers.md#merge-policy). A change that needs Dan gets a gate with exact options and worker link, while independent authorized work may continue.
6. Account for every known worker: working, waiting on Dan, waiting on access, awaiting merge, finished, or explicitly abandoned. Run `bd stale --days <threshold in days, rounded up>` and flag anything under the root; report what was checked and last observed. Retry only a cause understood within the same authorization. After repeated failure, stop the affected job and surface the blocker rather than silently substituting a provider or design.
7. Triage new `discovered-from` follow-ups, checking each against existing issues with `bd search` before accepting it. Settle completed workers only after the shared checks. Recompute capacity, then launch the next `approved` units from `bd ready` within limits. A pause or stop recorded by Dan prevents refills. Planning work obeys Wayfinder's active-map rules; ordinary chase cannot start it.
8. Before ending, make sure every change is on its issue. Close accepted no-PR work; merged work was closed by its worker. Open merge-ready PRs remain owned in Backlog. Follow [the board](../dispatch/references/board-page.md). Surface newly blocked-on-Dan, merge-ready, or finished work; keep healthy source-thread chatter for the digest, but always render the board in this turn. Comment the last successful chase on the root. A notification or user request can trigger the next pass; no cadence is created or promised.

Status and digest callers use reconciliation-only mode: read and record reports and surface gates, but skip follow-ups that start work, launches, refills, and settlement. An external event that supplies evidence to Wayfinder cannot advance its human decisions or refill planning workers.
