# Report

Verify current root ownership and a reachable Beads graph per [project state](../references/project-state.md) before any write or worker action. A non-owner may inspect only; takeover must be explicit.

A direct `/dispatch report <issue-id>` request or a chase found a worker report. Finish the step in hand, then process it. Read the [worker contract](../references/cooper-workers.md).

1. Resolve the issue, its owning worker and saved T3 destination. Read the complete T3 reply and the issue's new comments, notes and metadata, not a file path on another machine. Recover exact title/ID/link from the issue and live metadata. Check the report comment matches the reply; post a sanitized copy with source item/position, timestamp, attempt and head if it is missing, then advance `t3.cursor`. Preserve restricted evidence by reference with omissions noted. A repeat source marker does not start work again.
2. Check reported decisions against DECIDED and [reserved choices](../references/decisions.md). A departure remains a gate, even when checks pass. Report missing evidence precisely. Preserve Dan's questions with their owning worker links; new `human` decision issues the worker opened go to the top of the reply.
3. For a validator, read CONFIRMED/REJECTED and the model evidence. Recheck every auto-dispatch condition and capacity; otherwise propose it. Settle only after the shared checks. Do not launch a duplicate implementation for a validator report processed before a crash.
4. A Wayfinder result follows **Process planning reports** in [Wayfinder](wayfinder.md). Research evidence is not a user choice or build approval. Respect active/paused map and caller limits.
5. For implementation, read current PR/head/check/review state and compare it with `pr.head`. A new head needs fresh verification. Cooper owns its authorized PR watches; report notifications and explicit chase reconcile the graph. A worker that merged under `merge:auto` has closed its issue: confirm the merge SHA on GitHub and that the merge policy really allowed it, and flag any merge that broke the policy to Dan at once. A `human` merge-ready PR goes on Dan's list with the actual owning worker link beside it. When a `human` PR has merged, close its merge decision with who merged it.
6. A final report does not finish an open-PR job. Triage the worker's `discovered-from` follow-ups as their own items, never as silent scope expansion. Settle only after all shared checks, a closed issue or explicit handback, and safe artifact preservation.
7. After the batch, recompute authorized ready work and capacity with `bd ready`. A direct report/chase may refill existing authorization; status/digest skips all launches and settlement. Externally delivered Wayfinder evidence cannot start or refill planning. Reconcile current owner runtime after the report, including follow-ups and resumed runs. Render the [standard board](../references/board-page.md) before ending.

If the work came from Slack or another messaging conversation and you have access, post newly verified PR, blocker, merge, or deployment updates in that source thread. Include the PR link and actual status, and check `source.sender` and `source.milestone` to avoid duplicates. These updates do not wait for the digest. Other healthy routine changes wait for the digest. Surface newly blocked-on-Dan, merge-ready, merged, or finished work. Record missing reports or failed required T3 notifications as their actual failure, without duplicating workers.
