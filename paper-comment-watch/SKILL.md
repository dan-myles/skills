# Paper comment watch

Turn Paper comments into a work queue. A small script polls the Paper desktop MCP every second and prints one line per new comment. You get each line as a notification, do the work in Paper, and resolve the thread.

Scripts live next to this file. `<skill-dir>` below is the directory containing this `SKILL.md`.

## Setup

1. Load the Paper guide once per session: `get_guide({ topic: "paper-mcp-instructions" })`.
2. Resolve the file ID with `get_basic_info` (or `list_files`). Paper only lists comments for a file that is open in the desktop app, so ask the user to keep it open.
3. Arm the watcher. In Claude Code use the Monitor tool:
   - command: `python3 <skill-dir>/scripts/watch.py <fileId>`
   - timeout_ms: `1800000` (the maximum)
   - description: `new Paper comments on <file name> (polled every 1s)`
4. When the monitor expires, re-arm it with the same command right away and tell the user in one line that nothing came in. Keep going until the user says stop. Run one watcher per file; stop the old task before starting a new one.

Without a Monitor tool (Codex and others), start the same command as a background process writing to a log, and check the log between tasks.

## Events

| Line | Meaning |
| --- | --- |
| `NEW_THREAD <id> <author>: <preview>` | New open thread. Handle it. |
| `NEW_REPLY <id> <n> messages` | Someone replied on an open thread. Read the latest message. |
| `WATCHER_ERROR <reason>` | Five failed polls in a row: Paper closed, file not open, or MCP down. Tell the user once and keep the watcher running. |
| `WATCHER_OK` | Recovered. |

The script remembers what it has seen in `~/.cache/paper-comment-watch/<fileId>.json`, so a re-armed watcher only reports changes. On first run it reports every open thread, which is the backlog to work through. Pass `--reset` to forget state, or `--interval <seconds>` to slow polling.

## Handling a comment

1. `get_comment_thread` for the full text, the pinned node, and the page.
2. Skip it if the latest message is yours or it is only a reaction.
3. Screenshot the pinned node, or its artboard, to see what the comment points at.
4. Make the change. Follow the Paper guide's incremental writing rules and any taste the user has stated before.
5. Screenshot again and check spacing, type, contrast, alignment, and clipping. Fix problems before moving on.
6. `set_comment_thread_status` → `resolved`. The Paper MCP cannot post replies, so tell the user in chat what changed, in one or two lines per comment.
7. `finish_working_on_nodes` when the batch is done.

If several comments arrive together, work through them in order and resolve each one as you finish it. If a comment is ambiguous, make the most reasonable reading, say what you assumed, and resolve it. The user can reopen it. Ask first only when the change would destroy work the comment did not mention.

Record recurring feedback, such as banned styles or preferred type sizes, in memory so later comments and sessions start from it.

## Large writes

`scripts/paper_mcp.py` calls any Paper tool over the same local endpoint:

```bash
python3 <skill-dir>/scripts/paper_mcp.py write_html \
  '{"fileId":"<id>","targetNodeId":"<node>","mode":"insert-children"}' \
  --html-file /tmp/section.html
python3 <skill-dir>/scripts/paper_mcp.py duplicate_nodes \
  '{"fileId":"<id>","nodes":[{"id":"<artboard>"}]}' --full > /tmp/dup.json
```

Use it for HTML generated by a script (charts, maps, long lists) and for results too big to read in full, like the `duplicate_nodes` ID map. Without `--full` it prints `OK` and the first new node IDs. Override the endpoint with `PAPER_MCP_URL` (default `http://127.0.0.1:29979/mcp`).

## Paper gotchas

- Text color does not inherit. Set `color` on every text node.
- Colored inline `<span>`s render in the parent color. Put differently colored text in separate nodes inside a flex row.
- `create_artboard` ignores `left`/`top`. Position artboards afterwards with `update_styles`.
- Prefer fixed px over `calc()` and percentage offsets.
- Absolute children work inside a `position: relative` frame.
- There is no page delete tool. To consolidate pages, move artboards and ask the user to delete the empty pages.
- `paper-gen://` image generation counts against the user's usage. Only generate images when asked, and report the usage after each round.
