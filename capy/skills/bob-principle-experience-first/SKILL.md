# Experience first

When what's easy to build conflicts with what's good to use, pick what's good to use.

- Every feature, control, and option has to earn its place.
- Ship less and better: three polished features beat ten rough ones.
- Try the design in something throwaway, like an HTML mock, before building it for real.
- Get the details right: transitions, spacing, feedback, empty and error states.
- Everything should serve the main workflow or get out of its way.

The user is whoever consumes the work: the end user of a UI, the engineer importing a library, the next person maintaining the code. Explain impact from their side.

`bob-principle-foundational-thinking` sets the order of the work. This sets the target.
